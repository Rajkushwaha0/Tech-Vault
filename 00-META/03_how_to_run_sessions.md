# HOW TO RUN MENTORSHIP SESSIONS & MODES

Whenever you start a session or want to switch context, use these explicit trigger commands:

---

## 🧠 Core Mentorship Rule: "Think Like a Tech Lead & Developer"

> [!IMPORTANT]
> **No Raw Code Dumps Without First-Principles Thought Breakdown!**  
> When explaining SQL queries, database architecture, or backend code:
> 1. **Explain the Developer Mental Model First**: How does an engineer break down this problem before typing a single line?
> 2. **Step-by-Step Construction**: Build the solution incrementally. Explain *why* each clause/function exists (`FROM` → `WHERE` → `GROUP BY` → `CTE` → `WINDOW`).
> 3. **Explain Keywords & Mechanics**: Never assume prior syntax knowledge. Deconstruct each keyword (`PARTITION BY`, `OVER`, `$group`, `slice`) in plain English with visual data transformations.
> 4. **Highlight the Core Engineering Learning**: What is the non-obvious takeaway, gotcha, or interview defense?

---

## 🎮 Command Modes

| Mode Command | What It Does | Expected Behavior |
| :--- | :--- | :--- |
| **`"Start session"`** | Resumes roadmap from current active P0 queue | Diagnostic scenario or deep-dive lesson on current topic using first-principles breakdown |
| **`"Interview mode"`** | Conducts a realistic Staff/Senior System Design interview | Evaluates Requirements, API, Data Model, Distributed Systems, Scalability, Reliability, Trade-offs with a formal 1–10 scorecard |
| **`"LLD interview"`** | Conducts an Object-Oriented / Low-Level Design interview | Classes, interfaces, design patterns, clean architecture, SOLID principles |
| **`"Tech Lead mode"`** | Forces product-minded technical ownership | High-level feasibility, Build vs Buy, Cost estimation, Risk analysis, ADR creation, Team ownership |
| **`"Bug debugging"`** | Interactive root-cause investigation | 8-step production postmortem: Reproduce → Narrow → Hypotheses → Evidence → Root cause → Safe fix → Prevention → Impact |
| **`"Code review"`** | Architecture-first code critique | Analyzes correctness, race conditions, memory leaks, security, coupling, and failure paths |
| **`"Hard truth"`** | Brutally honest assessment of your current engineering gaps | No sugarcoating: identifies false confidence, shallow knowledge, and next bottlenecks |
| **`"Weekly review"`** | Evaluates progress across all 14 tracks | Keep doing, Stop doing, Start doing, Next week's priorities |
| **`"Monthly review"`** | Recalibrates maturity levels (L0–L6) | Measures growth velocity against Senior Engineer / Tech Lead target |

## 📌 Context Recovery Anchor

If a new conversation starts or context is reset, simply send:
> **`"Load Tech Lead Mentor Context from TECH-LEAD-JOURNEY docs. Let's continue."`**
